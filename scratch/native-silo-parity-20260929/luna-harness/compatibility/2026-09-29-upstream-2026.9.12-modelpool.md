# Upstream 2026.9.12 Windows release and empty-visual guard

## Finding

The official `2026.9.12` tag is marked latest on the release page (`9b491ff`). Its source does **not** include the empty-visual guard in `CModelPool::Exists`: it verifies `xr_strlen(N)`, copies/converts the string, searches the pool, then calls `Create(N, 0, false)` with no null/empty early return (`src/Layers/xrRender/ModelPool.cpp`, tag lines 413-438). Production `Create` only rejects an empty name under `_EDITOR`, which is not the retail path (`src/Layers/xrRender/ModelPool.cpp`, tag lines 222-226). The tag's `CHangingLamp::net_Spawn` immediately calls inherited `net_Spawn` and has no empty visual gate (`src/xrGame/HangingLamp.cpp`, tag lines 87-99). Inherited `CGameObject::net_Spawn` takes `CSE_Visual::get_visual()`, calls `Render->models_Exists(visualName)`, and selects the configured fallback only after that lookup returns false (`src/xrGame/GameObject.cpp`, tag lines 266-279).

This is the same source contract implicated by the Windows log's `CModelPool::Create` stack. Since the newest official source still lacks the guard and the release notes list no such fix, either official binary package is **unlikely to solve this failure**. This is a source-based compatibility assessment; I did not download or inspect the release binaries, so it is not proof of the exact retail machine code.

The repository describes MT-TEST as sharing standard Modded Exes features plus the MT renderer/scheduler paths, and explicitly flags an increased chance of crashes while loading the game or a save. It is therefore a poor compatibility workaround candidate for the present load/spawn failure.

The official install instructions say to unpack **all archive directories** into the Anomaly game folder with overwrite, then clear the launcher's shader cache once. That indicates the supported package unit is the archive, not a hand-picked EXE replacement. The archive may include corresponding engine/config/script payloads; because the task is protecting the installed GAMMA source, any inspection should target a separate runtime clone and preserve its mod content. The official troubleshooting reinstall procedure deletes/replaces broad `db/mods`, configs, scripts, and shaders, so it must not be applied to the user's GAMMA install.
