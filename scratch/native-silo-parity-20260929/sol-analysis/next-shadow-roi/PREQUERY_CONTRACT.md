# Current-frame GPU eligibility before local shadows

**Decision: qualify one bounded, observe-only single-volume query experiment. Do not implement culling or mid-frame resume yet.** The experiment can establish conservative coverage, zero usefulness and added observer cost without splitting or waiting on a command buffer. No code/build/GPU/game action was performed for this audit.

## Entry point and minimal query

Use the local-light block at `MetalR4EngineScene.mm:4960`, after world G-buffer (`4572–4644`), HUD G-buffer (`4675–4706`) and scope depth restore (`4709–4735`), and before `renderLocalShadowBatch` at `5179`. At this point the actual geometry bit/depth are available. Sun/emissive accumulation has already run; the query reads only stencil bit 0, so high marker bits do not determine its admission.

For each selected planned shadow face, issue **one** draw of its exact accumulator volume with the existing admitted `accum_volume.vs`, unshadowed Point/Spot PS family, current per-light immutable VS constants, actual viewport, clockwise winding and the final accumulation's front-face cull. Set depth compare Always, depthWrite false, stencil Equal with reference 1/readMask 1/writeMask 0 and Keep operations, and color write mask 0. Load/store the existing attachments without clear. All original shadow, accumulation and volumetric draws still execute. Never reinterpret a skipped/invalid/unencoded face as zero.

The final local draw uses the same volume/VS/cull/depth Always, but a stricter full-marker stencil comparison (`LocalLightAdapter.cpp:344–394`). Its receiver coverage is therefore a subset of the geometry-bit query's projected coverage. The qualified source `build/metal-shader-sources/r3/accum_omni_unshadowed.ps` and `accum_base.ps` has no discard/clip in either main; shadow changes an output factor, not raster admission. Source identity is pinned by `build/metal-runtime-shaders/local-lights/local-lights-msc-receipt.txt`. This source argument still needs actual-PSO counter qualification and conservative same-frame correlation. The one-draw query will be loose: walls projected inside a light volume can make it nonzero while the final Carmack mask has zero receivers.

Do not start with the three front/back/accumulation mask draws. Their mask PSOs write stencil bits (`LocalLightAdapter.cpp:369–378`). Running them on production stencil, even with color writes disabled, changes renderer state. An isolated depth/stencil copy or a fully qualified restore costs bandwidth and adds scope; a reset alone is not proof that every later consumer's state was preserved. Reject that larger initial design.

## One cheap diagnostic and ownership

Select at most eight complete parent groups/48 faces for 12 acquired frames, as V6 did. Encode the prefix query pass and continue the **entire existing** shadow/accumulation graph in the same command buffer. Read both result channels only in its normal completed handler. There is no GPU wait, second Prewarm, scene reentry, CPU consumption of a same-frame query before submit, or previous-frame decision.

Use two bounded 48×uint64 result banks and separate ledgers, one for prefix eligibility and one for final deferred receivers (768 result bytes/acquisition). Do not append duplicate light IDs to the existing V6 ledger: it rejects duplicate IDs and caps at 48 slots (`R4WholeLightVisibilityLedger.h:67–114`). Join by acquisition epoch, submitted serial, engine frame, immutable snapshot identity, group/light ID and face, with a phase tag. Retain both banks/resources until command completion; discard/retry, failed allocation, overflow, missing receipt or partial group gives unknown, never zero. Current completion plumbing already snapshots epoch and owned records at `MetalR4Backend.mm:2415–2423` and classifies only completed commands (`:176–202`).

Before any live observer run, use a small actual-PSO oracle to verify unchanged raw color/depth/stencil, positive/nonzero receiver cases, near-plane/camera-inside cases and current-frame phase ownership. In the observer, require **prefix count ≥ final count for each complete same-frame face**; any prefix-zero/final-nonzero pair is a failed conservative gate. Record prefix-zero/final-zero groups and their matched CPU work counters, and prefix-nonzero/final-zero misses. There is no suppression in this test.

The GPU draw count is at most 48 extra volume draws per observed frame: Spot is 32 triangles, OmniFace uses the actual 160-triangle `du_sphere_part` mesh. Fragment cost at full resolution is unknown. Time the observer CPU preparation/encode as one bounded interval; if available, an isolated GPU counter interval around the query pass measures its elapsed execution span, not GPU active time. Whole-command-buffer GPU elapsed cannot attribute this pass or CPU cost. Keep detailed per-bind timers off.

## Opportunity and stop rule

V6's old fixed-camera diagnostic selected 96 complete group observations across 12 frames: 88 zero groups/468 zero faces carried 11,016 static rows, 1,713 static encoded draws, 1,393 dynamic draws and 2,820,096 transform bytes. Those are repeated selected observations, not all scene lights or measured avoidable time. Flora work and CPU stage costs are not included in that table. No FPS inference follows.

This is enough source/evidence signal for **one** cheap eligibility screen. If the loose prefix produces no useful complete zero groups, misses essentially all final zero groups, breaks conservative correlation, or adds substantial cost, reject it without adding a stencil copy, a custom rasterizer or a GPU wait. Useful zero/work correlation would justify separately auditing a current-frame split/resume design, but would not prove net performance: a GPU round trip can erase the prospective CPU saving. Current `SubmitFrame` is the final submit/presentation transaction; it is not a safe mid-frame flush. Ownership, temporal/pose commit/discard, pinned acquired-slot resources and no-second-Prewarm semantics would need a separate proof before any CPU work is skipped.
