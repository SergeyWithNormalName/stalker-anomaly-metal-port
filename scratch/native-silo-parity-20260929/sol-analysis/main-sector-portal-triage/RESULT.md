# Main Flora sector/portal membership: feasibility triage

## Result

A low-cost, fail-open observer is feasible without inventing sector heuristics or replaying portal math: Direct Metal's current `CRender::Calculate` path already calls `detectLastSector(Device.vCameraPosition)` and `GMBase.traverse(...)` using that frame's camera matrix before world capture. After traversal, read the existing `GMBase.m_sector_frustums` map and serialize only visible sector ordinals plus their root visual indices. Join those roots to static visual descendants using the existing frozen `CollectR4StaticVisualDescendants` parser. This would observe the exact source sector/portal result for that frame; no HOM geometry result should be used for suppression, and no draw should be changed.

The active `l01_escape/level` SHA-256 is `1800a451d0bba9af1da69fae8683b36b6e6346709c0d6b9bf14385f4a48d19f7`; `level.geom` is `a4552d34eec6f87ed7eb461327c8a331d1f7a3b9911a2b51342ca4d377f8d78a`; active `level.cform` is `6a8e56d483d60da0f461fb2e20ca64ba193b94ed883013c337c7d293a2410e31`. The level chunk scan found 32 sector records, 128 packed portal records, and 256 sector-to-portal references. Every sector has one valid root visual index.

Using the existing level visual chunks' OGF linked-child IDs, all 5,316 exact frame-700 main-Flora IDs are assigned to exactly one sector-root descendant closure: 5,308 under sector 30/root visual 21910 and 8 under sector 3/root visual 22397. ## Source contract and limits

`CRender::LoadSectors` reads `fsL_PORTALS` as packed `b_portal` records and `fsL_SECTORS` as nested sector chunks. Each sector lists portal IDs in `fsP_Portals` and a root visual ID in `fsP_Root`; `CSector::load` resolves those references. `CSector::traverse` follows only portals accepted by its sphere/frustum, neighbor-selection, source SSA/fade, and optional HOM tests, then stores sector frustums in `CDSGraphManager::m_sector_frustums`. `r_dsgraph_capture_static` draws each visited sector root with its accumulated frustums. These contracts are in `src/Layers/xrRenderPC_R4/r4_loader.cpp`, `src/Layers/xrRender/r__sector.cpp`, and `src/Layers/xrRender/r__dsgraph_render.cpp`.

Starting-sector selection is also source-defined: `detectLastSector` ray-queries `rmPortals` (then checks the candidate sector root box); if that fails it ray-queries `g_pGameLevel->ObjectSpace.GetStaticModel()` and uses the hit triangle's sector. The fixed frame's stored eye/matrices alone are insufficient to reproduce that result exactly without parsing active CFORM sector tags and mirroring ray-query tie behavior. The active `level.cform` is present, but the frozen `R4LevelGeometry` parser handles only `level` visual/shader chunks and `level.geom` buffers; it does not parse `fsL_PORTALS`, sector roots, CFORM, or the source frustum traversal.

Accordingly, the safest minimal diagnostic is a frame-700-only, CPU-only readout immediately after the existing `GMBase.traverse` call in the already instrumented Direct Metal `R_calculate.cpp`: record frame/eye/matrix bits, the detected start-sector ordinal, and each `m_sector_frustums` sector ordinal, frustum count, and sector-root index. Offline, join those root indices to descendants and the 5,316 exact IDs. If the source frame marker, active level hashes, start sector, any root index, or descendant coverage is missing or inconsistent, mark membership unknown and fail open. This avoids a new traversal implementation and avoids relying on unqualified HOM triangles, physics bounds, material names, or approximate geometry.

The observer could identify captured Flora in sectors absent from the source visible-sector set; it cannot by itself prove each remaining tree survives the source root-level frustum, static SSA/fade, emissive, or exemption gates. Do not turn sector membership into a suppression list. A useful follow-up would compare observed visible roots against frame-700 exact IDs and report only the one-sided “sector not visited” count as a topology candidate, with no FPS claim.
