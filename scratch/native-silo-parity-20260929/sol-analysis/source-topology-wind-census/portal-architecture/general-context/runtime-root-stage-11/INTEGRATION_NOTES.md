# Stage 11: defer Flora portal proof until after camera clipping

This is a scratch-only candidate composed from the immutable stage-10 source snapshot. It changes three copied renderer files and adds no helper: `MetalR4EngineScene.mm`, `MetalR4FloraAdapter.h`, and `MetalR4FloraAdapter.cpp`. `BASE_FROM_STAGE10_SHA256.json` records the original copied inputs; `SHA256.json` records base and candidate hashes; `candidate.patch` is the review diff.

`XRAY_METAL_FLORA_PORTAL_DEFER_AFTER_CLIP` is enabled only by the exact value `1`; the default-off path still builds and applies the existing full prepared exclusion set. When enabled for the per-frame suppression path, the scene first qualifies the current portal frame and the complete immutable source/rest population. It reuses a dense visual-ID-to-rest-record lookup only while generation, rest-vector pointer, and count still match. View/projection/eye, drawable extent, frame, portal generation, wind snapshot, and environment snapshot remain checked for each callback. The cheap population-only qualification does not prepare motion; a single `PreparedMotion` is created after it succeeds and is used by the synchronous draw callback. Reset/Prepare replaces the owning scene implementation, so the cached lookup is scene-generation scoped.

The adapter preserves source order and the existing camera clip test. Only a draw that survives that exact clip reaches the deferred predicate; the predicate then performs the current-frame raw portal candidate check, exact wind-envelope calculation, and owner-frustum proof before any per-draw uploads. An unknown record, bad index, missing owner/reached-frustum data, invalid wind bound, or exception keeps the draw visible. The shadow path is untouched. If any outer qualification fails, the ordinary unmasked draw runs.

The observe-only pixel-oracle branch retains the full helper as an expected-decision reference and compares each camera-surviving visual ID against the lazy result. A mismatch makes validation fail; this is an ID-set comparison at the actual post-clip seam, not a count comparison. The ordinary OFF oracle branch remains unchanged. Lazy telemetry distinguishes camera-surviving portal candidates, wind calls, owner-record checks, owner-frustum tests, unknown-kept-visible decisions, mismatches, and actual skipped draws. `prepared_exclusions` remains zero in lazy mode and is not used to imply that a full per-ID vector was constructed.
