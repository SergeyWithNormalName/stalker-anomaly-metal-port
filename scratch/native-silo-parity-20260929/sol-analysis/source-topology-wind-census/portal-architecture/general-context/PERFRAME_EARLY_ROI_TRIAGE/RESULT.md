# Per-frame portal + wind early-ROI hypothesis

Read-only source triage for the stage-10 default-off portal candidate. No production source, build, or game changes were made.

## Hypothesis

The cheapest broadly safe place to avoid outdoor wind-envelope work is the Flora adapter's existing per-draw camera-clip point, rather than an outdoor-sector check or a heuristic early-exit threshold. Stage-10 currently computes portal/wind exclusions for the frame before the ordinary Flora draw loop. In that loop the adapter then performs its exact source-order camera clip test before applying the sorted exclusion list. This means it already knows which records are off the current camera before those records can affect actual post-clip skips.

The next scratch-only design to evaluate is a validated per-generation direct lookup from `visualId` to its immutable rest/material/owner record, plus the current frame's portal broad-phase membership and graph result. Preserve the portal graph's broad-phase test. In the unchanged source-order draw loop, keep the existing camera clip first; only for a draw that survives it and is also outside the reached portal frusta should the code compute the current-and-previous wind envelope and exact owner-frustum tests. Prepare and validate the complete generation join once, retain the lookup only while generation, adapter population pointer, and count match, and invalidate it on `Prepare`/`Reset`. Recompute the motion snapshot validation once per frame; never cache its benders or the frame graph. Exclude that visual only when every existing qualification succeeds. Missing IDs, incomplete generation joins, stale camera/view/extent/motion, unknown rest extrema, uncertain bender normalization, unknown owners, exceptions, and nonfinite inputs must keep the draw. This policy has no sector-ID, pose, or scene-specific branch and has no rejection threshold that could suppress valid work.

It reuses the clip result already required by ordinary drawing, rather than pre-running a second clip pass. The exact clip contract is concrete: the adapter transforms its referenced local AABB by the current `projection * view * model`, and rejects only when all eight corners are outside one Metal clip plane; missing/invalid inputs fail open. A candidate predicate should run after that check and before upload/bind work. This preserves source draw order and leaves the shadow callbacks untouched.

The narrow seam is a synchronous optional per-draw decision context for the existing main Flora callback. Validate the frame/view/extent, generation, complete population lookup, and prepared current+previous motion once before entering the adapter. After the ordinary clip, the adapter supplies only `visualId` to a read-only resolver: if the generation-owned record or same-frame raw portal result is missing/visible, keep; otherwise compute the existing envelope and owner checks from the retained rest record and current reached-frustum graph. Unknown per-draw inputs keep that draw. Keep the current full-set helper and ordinary draw path as the disabled/default fallback. This adds an API boundary and lifetime review, but avoids a second clip pass, a copied exclusion set, and wind calculations for offscreen entries.

## Evidence and limits

The exact stage-07 frame-700 join is saved in `camera-clip-opportunity.json` and reproducible with `quantify_calls.py`. It intersects the ordinary adapter's source-ID capture (written after its camera clip) with same-frame `raw_visible` flags from the portal graph. `raw_portal_candidates` is incremented immediately before one `flora_wind::compute` call in the candidate builder. The table therefore counts wind computations that could be deferred past an already-existing clip test:

| Frame-700 pose | Prepared rest records | Camera survivors | Raw portal candidates / current wind computations | Raw candidates among camera survivors | Wind computations on already-camera-clipped draws | Candidate exclusions | Actual post-clip skips |
|---|---:|---:|---:|---:|---:|---:|---:|
| Indoor | 11,663 | 5,316 | 10,744 | 4,427 | 6,317 (58.8%) | 10,372 | 4,055 |
| Outdoor | 11,663 | 5,308 | 6,356 | 19 | 6,337 (99.7%) | 6,207 | 8 |

The camera-clipped exclusion counts are 6,317 indoors and 6,199 outdoors (`prepared exclusions - actual post-clip skips`). The outdoor survivor join contains 5,308 rows with no unknown join IDs, but its observer completeness flag is false because the separate validator pins 5,316 source IDs; treat the 19/6,337 split as measured on the captured outdoor subset, not a completed population qualification. Per-visual owner-frustum entry counts are not captured. Conservative bounds from the aggregate unknown counters put offscreen owner-evaluation records at 6,269–6,317 indoors and 6,305–6,337 outdoors; individual frustum-plane test counts remain unknown. These bounds subtract every reported wind/owner unknown from the offscreen candidate count, even though some unknowns may belong to other rows.

This hypothesis avoids per-visual wind (and the downstream owner tests) for records that the adapter will camera-clip anyway. It does not avoid per-frame graph traversal or motion snapshot validation. Stage-10's indoor fast-path sample measured 1.81 ms p50 for the mask and 0.72 ms for graph traversal; their 2.52 ms sum is the indoor sample only. No outdoor per-frame CPU timing exists yet. These call counts indicate that the seam is worth a small isolated draft, especially for the recorded outdoor pose, but do not establish CPU time saved or FPS gain. The indoor path would still compute wind for 4,427 source-camera survivors. No helper benchmark was run; timing needs the root's scheduling approval.

## Falsifier before any integration

In a later isolated scratch experiment, record for the same qualified frame: raw portal candidates, exact source-camera survivors among them, wind-envelope calls, owner-evaluation records, exclusions, actual post-clip skips, and graph/mask CPU time. Compare the actual post-camera-clip suppressed ID set with the current full-set implementation; off-camera IDs need not be materialized as exclusions. Then rerun the existing indoor and outdoor MRT plus D32S8 readback oracle. Any changed actual skip ID, stale-input admission, or pixel/depth/stencil delta rejects the shortcut. If callback overhead cancels the eliminated work or candidate-building time does not fall while the current graph and full generation qualification remain intact, the optimization hypothesis is falsified. The outdoor 5,308/5,316 observer mismatch must be repaired before that pose can count as complete-population evidence.

No fixed IDs, owner-sector numbers, sector-count shortcuts, or saved-frame decisions are part of this hypothesis.
