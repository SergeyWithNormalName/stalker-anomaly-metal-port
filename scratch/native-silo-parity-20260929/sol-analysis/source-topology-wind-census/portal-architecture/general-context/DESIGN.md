# Cached source portal context draft

This scratch draft turns the prior pseudocode into three renderer-independent C++ helpers plus one frame-700 probe. It does not modify production sources or cull draws. See `draft/R4PortalGenerationContext.h/.cpp`, `draft/R4PortalGraphPreparedObserver.cpp`, and `draft/tests/R4PortalGenerationContextProbe.cpp`.

`BuildR4PortalGenerationCache` builds into a temporary and publishes only a fully qualified generation. It copies only parser-owned visual bounds and sector/portal/owner metadata, validates IDs and incidence, qualifies each portal polygon once, and runs `CPortal::Setup` once per portal. It retains the resulting planes and spheres as values. It also builds an owned `CDB::MODEL` from ordered portal fan triangles with portal IDs in the dummy field. A one-real-triangle model receives a remote sentinel-dummy triangle to meet the source CDB minimums; a sentinel hit falls through to the same-direction CFORM query. No real triangles means no portal model. `MODEL::build` is synchronous and copies collector arrays; the local collector then dies. The generation cache owns the model and value data until replaced.

`ResolveR4DetectLastSector` mirrors `CRender::detectLastSector`: one sector uses the source loader's largest-root-volume outdoor choice; otherwise query nearest portal downward then upward at range 1000, classify front/back at the eye, and accept only a sector whose root visual AABB contains the eye. An unaccepted nearest portal falls through to nearest static CFORM in that same direction, then the opposite direction. The supplied static CFORM `MODEL` is borrowed only for the call. Collider results are read immediately as numeric sector values; no `RESULT`, `TRI`, `CPortal`, or `CSector` pointer escapes.

`ObserveR4PortalGeneration` checks the generation token and frame snapshot, resolves the start sector, forces options to 6 (HOM off), then calls the prepared graph walker. The copied walker retains the source `CFrustum::CreateFromMatrix`, dirty sphere tests, polygon clipping, `CreateFromPortal`, and raw owner-frustum tests. It uses the cached portal plane/sphere array and does not repeat topology validation or `CPortal::Setup` per frame; clipped polygons still receive per-frame numeric validation. Output frusta are value-owned in `R4PortalGraphResult`. Any failed validation/query/generation/walk yields invalid output and a visible-all vector, never partial owner membership.

The frame-700 probe reuses the existing level/level.geom, ID, raw-flag, and matrix fixture, including the ID CSV's exact `encode_complete,5316` footer. Its static CFORM model is a tiny labeled test fixture (sector 25), not an engine-live CFORM snapshot; a separate fallback-only resolver check confirms it returns 25. The portal-first source resolver may produce a portal-facing sector, so the probe does not assume the captured vertical CFORM sector is its start-sector oracle: the final per-ID replay must match the frozen 5316-ID result. It also checks malformed topology rejection and stale-generation visible-all output. Root owns the actual engine-target build and execution; this draft has not been compiled or run.

No result is connected to render admission. The previous uncached C++ replay matched all 5316 per-ID results (889 visible, 4427 outside), reaching six sectors/eight frusta. The cached draft must reproduce that receipt before root considers wiring it to live frame metadata.
