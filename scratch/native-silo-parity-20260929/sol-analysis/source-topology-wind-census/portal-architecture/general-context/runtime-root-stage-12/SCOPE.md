This is a scratch integration draft layered on runtime-root-stage-10; it does not touch production files. The only new runtime experiment is gated by exact environment value `XRAY_METAL_COMPUTE_BOUNDS_SOURCE_CERTIFICATE=1` captured in `MetalR4DynamicWorldAdapter::Configure`. With the gate off, cached canonical vertices remain in the existing vector and the original bounds function is called. With it on, a ready canonical stream is moved once into the immutable certificate, so the certificate is the only retained canonical CPU vector; the existing GPU input upload reads that same stream through one accessor. Geometry, canonical bytes, dispatch inputs, fallback route, and GPU ownership remain unchanged.

The bounds call uses the certificate only when that owned certificate exists. All other calls retain the baseline function. E07 output gains per-frame compute-bounds call and source-vertex counts, plus a separate `compute_bounds_ms` timer so this path does not get mixed into the existing fallback `bounds_ms` field. The timer runs only when E07 profiling is enabled; no per-vertex timing was added.

`runtime-root-source-hashes-v12.json` records the inherited stage10 files plus the changed adapter, CMake source list, and new helper files. The root owns any temporary build/restore transaction and any runtime observation. No build or game run was performed for this integration draft. It remains uncompiled and unvalidated as an application candidate.

The separate CPU probe package is at `../../../../compute-bounds-immutable-hypothesis/RESULT.md`; it established CPU-only parity and timing, not a live renderer benefit. This integration is a measurement candidate only, with no culling or draw-suppression behavior.
