# Primary Calculate to cached portal-context seam

Keep the observer synchronous and value-only across the existing R4 scene lifetime. `MetalR4EngineScene::Prepare` already calls `prepareLevelScene`, which fills `impl->scene.geometry` via `LoadR4LevelGeometryWithBytes`; the parser-owned `portalMetadata`, visuals and bounds remain in that `LevelScene` after `geometryBytes` is cleared on upload commit. Build `R4PortalGenerationCache` from `impl->scene.geometry` once after the level-scene parse succeeds. Do not load or parse a second copy and do not change `MetalBootstrap.mm`. Gate cache construction behind one default-off observer flag. Cache failure leaves the scene prepared and records an unavailable reason; it must never fail gameplay `Prepare`.

Own that cache in `MetalR4EngineScene::Impl`, beside `LevelScene`. Give each successful prepared-level lifecycle a monotonically increasing generation value and retain it with the cache. `LoadLevelScene` already calls `scene.Reset()` before preparing a different normalized path; `UnloadLevelScene` also resets; `Prepare` begins with `Reset`. Replacing `Impl` therefore retires the old portal model and its parser-derived values as one unit. The same-path early return keeps the current generation. If a new `Prepare` cannot qualify the cache, its status is unavailable for that generation and every observe call fails open.

The narrow cross-layer seam is one synchronous method on `MetalR4EngineScene` that accepts a `R4PortalContextFrameInput` by value and a borrowed `const CDB::MODEL*` for static CFORM, calls `ObserveR4PortalGeneration`, and returns `R4PortalContextFrameOutput` by value. A forwarding method on `MetalRenderDeviceRender` lets the R4-only `CRender::Calculate` branch invoke the owned scene without exporting `Impl` or storing a CDB pointer. The call does not retain the borrowed static model, a `CDB::COLLIDER`, or any query result. `MetalRenderDeviceRender` owns the prepared scene and already resets it at `LoadLevelScene` / `UnloadLevelScene`, so no separate graph registry or callback framework is needed.

Place the call in `src/Layers/xrRender/R_calculate.cpp` after its existing `sceneReady` check and after it computes this frame's SSA factors, before returning from the `SelectedR4Backend()==Metal` branch. That location has the authoritative current `Device.dwFrame`, `Device.vCameraPosition`, `Device.mFullTransform`, and the freshly calculated `r_ssaDISCARD`/`r_ssaLOD_A/B`; `g_pGameLevel->ObjectSpace.GetStaticModel()` is valid for the synchronous call. Capture `Device.vCameraPosition_saved` separately for the source near-dual-render test, `VIEWPORT_NEAR` for the portal camera-near threshold, and `psDeviceFlags.test(rsDrawPortals)` for the portal flag. The source-sector traversal uses the saved camera position (`r__sector.cpp`), while `Calculate` passes current `Device.vCameraPosition` as the graph eye. Pin options to `6` for this HOM-off observation. The `LevelScene` generation is attached inside the device/scene forwarding method, so `Calculate` only supplies same-frame values.

The intended seam touches at most eight implementation files: the three cached-context helper files already in `general-context/draft/`; `MetalR4EngineScene.h/.mm`; `MetalRenderDeviceRender.h/.mm`; and `xrRender/R_calculate.cpp`. `MetalRenderDeviceRender.h` is already included as an Apple-specific bridge in `dxEnvironmentRender.cpp`, and `R_calculate.cpp` is listed in the R4-specific CMake target, so keep the include/call behind the Apple + Metal selection branch. This leaves the R1/R2/R3 Calculate paths alone.

Return only observer status, generation/frame IDs, resolved start sector, and value-owned owner frusta. Do not hand the result to dsgraph insertion or any draw/shadow adapter. The only allowed output consumer in this seam is the scratch diagnostic receipt. A missing level, unavailable cache, stale generation, non-finite frame value or failed query produces unavailable/keep-all and does not change `GMBase`, admission, or frame encoding.

No source edits or runtime integration were made for this note. This is the smallest proposed wiring after the independent cached-context probe passes; the earlier synthetic CFORM fixture validates only the API contract, not live `ObjectSpace` behavior.
