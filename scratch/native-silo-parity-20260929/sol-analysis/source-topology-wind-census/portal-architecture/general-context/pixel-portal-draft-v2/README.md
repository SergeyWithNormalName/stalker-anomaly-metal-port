# Scene-owned portal pixel-oracle draft v2

This is an immutable v2 scratch copy of `pixel-portal-draft`. It adds freshness and completeness gates before creating a source-vs-portals mask. It does not modify production files, adapter files, shaders, build outputs, or game state.

The OFF/ON oracle remains inside the scene-owned G-buffer pass, after terrain and before the existing world callback. It compares cloned pre-Flora MRT/depth-stencil state, renders the OFF branch with all source-order Flora draws, and renders the ON branch with only validated candidate IDs filtered after ordinary camera clipping. The production callback still runs once afterward in source order. Shadow submissions remain outside this mask.

Before candidate construction, the prepare callback now requires `floraMotion.valid` and `floraMotion.engineFrame == callbackView.engineFrame`, plus `floraEnvironment.valid` and `floraEnvironment.engineFrame == callbackView.engineFrame`. The helper repeats these freshness results as explicit inputs. The frozen view's copied frame number and `windValid` bit alone are not treated as freshness proof.

Candidate construction requires exactly 5,316 rest records and the adapter telemetry's admitted-draw count to match. It independently derives the known type-7 Flora ID set from the retained level geometry (tree lighting plus the exact leaf/trunk shader names) and requires exact set equality. Every record ID must be unique and map to an unambiguous source visual and portal node, with valid vertex/index ranges. A missing, duplicate, extraneous, or structurally unjoined source ID disables the whole candidate mask. Once the complete ID set is established, an individual record with unknown rest bounds, invalid eligibility, empty/invalid owners, or incomplete owner frusta is kept visible. The excluded-ID list is sorted and unique for the adapter validation seam's membership check; it does not reorder draws.

The oracle still requires a nonempty candidate set, a nonzero actual post-camera-clip skip count, consistent per-branch telemetry, source-order `mProject * mView` full-transform equality, exact four-MRT comparison, exact D32S8 comparison, and nonblank Flora output. Raw portal flags only nominate broad-phase candidates; the existing outward-rounded rest-plus-wind union bound and every owner-sector frustum are required for an exclusion.

The adapter's rest metadata is default-off and requires `XRAY_METAL_FLORA_REST_METADATA=1`; the v3 adapter adds the matching validation-only filter wrapper. Those files remain separately owned and are not copied or changed here. This package is therefore a review draft, not a build-ready patch. No build or game run was performed. Even a later passing pair would qualify only the captured frame and pose; it would not establish general culling safety, shipping admission, or an FPS gain.
