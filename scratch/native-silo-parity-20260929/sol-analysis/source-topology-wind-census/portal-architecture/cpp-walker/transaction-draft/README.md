# Root-owned C++ source-frustum replay transaction draft

This is an offline C++ replay of the exact observer-v2 frame-700 inputs, not a new inside-game observer and not a source suppression feature. It parses the generation-1 copied `IReader` level bytes with the matching `level.geom`, takes frame matrices/view/near/SSA/portal flag from the pinned capture words, and starts from the measured live CFORM sector 25. `verify_inputs.py` checks the observer output and byte receipts before any probe run.

The staged tree contains the prior optional metadata parser draft plus the source `CPortal`/`CFrustum` observer and replay probe. The required metadata patch is `../cpp-metadata/metadata.patch`; `replay-target.patch` adds a one-off `XRay.Render.R4.PortalGraphReplayProbe` target. The target uses R4 compile definitions/force-includes and links `XRay.Render.R4`, `XRay.Engine`, `XRay.Core`, `XRay.Collision`, and `XRay.Metal.R4Backend`. This is needed because `CPortal::Setup` is in the renderer sector module and the source frustum methods are in XRCDB; if static archive extraction exposes further engine dependencies, let the build report them rather than replacing source math.

Suggested root transaction order: verify these staged/prestate hashes; apply only the parser and CMake patches; copy staged additions to their corresponding `src/Layers/xrRenderMetal` paths; build the new probe target; run `verify_inputs.py`; run the probe with the copied active level, matching geometry, Flora ID list, and previous raw-flag CSV; save its stdout and per-ID CSV; then restore all modified source files and ordinary app/bare executables under exact hash gates. No such install/build/run/restore transaction was performed here.

The expected comparison is the earlier raw OGF sphere+AABB partition (4,427 outside, 889 intersecting), not an asserted C++ result. The probe reports actual source C++ counts and per-ID differences without treating differences as build failure. A valid result remains an observer-only single-frame qualification; no hierarchy ancestor-mask, HOM, wind, temporal, shadow, or visual admission is included.

Start sector 25 is valid for this replay because the saved frame has two live vertical CFORM hits in sector 25 and the independent portal-first scan found no portal hit. This does not reproduce general `detectLastSector`: that source tests the nearest portal within range and root-box containment before static CFORM and has no carried prior-sector fallback if both fail. General lifecycle/start-sector ownership remains a later requirement.
