# Scratch Flora vertex-fetch observer draft

This folder contains an uninstalled backend-only draft: `MetalR4Backend.fetch-observer.draft.mm`, its exact pre-edit backup `base-MetalR4Backend.mm`, a focused patch, and the receipt contract in `VALIDATION.md`. Production `src/Layers/xrRenderMetal/MetalR4Backend.mm` was not edited. The original and backup both hash to `365115ea87703d4038a45b95e9a8decc4d0769f2b091159e253930c36892bebc`.

The draft is default-off. Set `XRAY_METAL_FLORA_FETCH_OBSERVER=1` and an absolute `XRAY_METAL_FLORA_FETCH_FILE` path to request one frame-700 receipt. It listens only inside the exact `R4 engine scene G-buffer` pass and for the exact main Flora leaf/trunk labels and shader keys. It never records shadow, dynamic, HUD, or unrelated pipelines.

The record joins the selected native PSO identity/label and copied vertex descriptor with the buffer binding/version and indexed draw fields. It requires Shared, non-frame-upload Vertex/Index buffers and reads only their CPU-visible immutable bytes. It hashes the full logical bound vertex-buffer range (`IR4Buffer::Size()`), excluding native allocation padding and the exact index byte range used by the draw, then checks every referenced index after `baseVertex` to confirm the fetched P4 W word at byte 12 is `0x3f800000`. If a descriptor, storage mode, buffer range, CPU mapping, hash, or W value is uncertain, the row says unknown or mismatch. The backend draw descriptor exposes no Flora visual ID; each row calls that out. Offline matching must join on the buffer identities/hashes and index tuple, and keep the match unknown if it is absent or ambiguous.

No app or game build, shader cook, GPU readback, game launch, or runtime run has been performed for this scratch draft. It has not been compiled. It changes no PSO descriptor, buffer bind, encoder state, draw arguments, visibility, culling, or GPU resource. The receipt is an observe-only source draft, not runtime proof or production admission.
