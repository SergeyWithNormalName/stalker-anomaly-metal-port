# OmniFace parity audit: existing candidate, weak prior economics

2026-09-29, read-only source/evidence review. No renderer implementation, build, game/GPU run or benchmark. Stop a new equivalent face-culling candidate; the implementation already exists, and the saved economic signal is small.

**Windows `r2_shadow_omnipart_vischeck=1` is not a pure per-face camera-frustum algorithm.** [light.cpp:594](<XRAY_SOURCE_ROOT>/src/Layers/xrRender/light.cpp:594) calls each child's `vis_prepare` rather than copying parent visibility. [light_vis.cpp:12](<XRAY_SOURCE_ROOT>/src/Layers/xrRender/light_vis.cpp:12) submits an occlusion query of that face's actual light volume against geometry stencil (volumetric Spot disables stencil), except near/inside, HUD, disabled-occq or not-yet-scheduled tests. [vis_update:86](<XRAY_SOURCE_ROOT>/src/Layers/xrRender/light_vis.cpp:86) uses asynchronous GetData and scheduled history, classifying more than four fragments as visible. [lights_render.cpp:78](<XRAY_SOURCE_ROOT>/src/Layers/xrRender/lights_render.cpp:78) removes invisible children before shadow-map work. Geometry invisible because of camera clipping can return zero, but so can on-screen geometry occlusion. Reproducing the full source policy would involve the forbidden query/history/wait branch; do not relabel it as a simple geometric parity check.

Native [MetalRenderDeviceRender.mm:997](<XRAY_SOURCE_ROOT>/src/Layers/xrRenderMetal/MetalRenderDeviceRender.mm:997) creates six value-only OmniFaces per active shadowed point parent. [planLocalShadowBatches:2595](<XRAY_SOURCE_ROOT>/src/Layers/xrRenderMetal/MetalR4EngineScene.mm:2595) first validates complete six-face source groups. Its ordinary parent admission retains all six when any conservative volume intersects the camera. It already has strict opt-in `XRAY_METAL_LOCAL_LIGHT_FACE_CULL=1` individual-face admission afterward ([line 2640](<XRAY_SOURCE_ROOT>/src/Layers/xrRenderMetal/MetalR4EngineScene.mm:2640)). Thus the observed ~285 faces is consistent with that flag being off; it is not evidence that the algorithm is missing.

The existing filter computes the padded world AABB of the real `du_sphere_part` accumulator mesh ([LocalLightAdapter.cpp:723](<XRAY_SOURCE_ROOT>/src/Layers/xrRenderMetal/MetalR4LocalLightAdapter.cpp:723)), then requires all corners outside one of six homogeneous current-camera clip planes with float roundoff margins ([R4LocalLightFaceVisibility.h:31](<XRAY_SOURCE_ROOT>/src/Layers/xrRenderMetal/R4LocalLightFaceVisibility.h:31)). Touching, invalid or uncertain data stays visible. It removes complete records, including all caster preparation, shadow draws and that face's deferred volume draws. It does not occlude anything that is merely hidden behind geometry.

| Forward/water/particles/rain | Current inspected adapters have no direct local atlas binding; they can consume accumulated lighting downstream. | Secondary views | Current EngineScene submission guard allows one primary world view; its temporal lifecycle probe explicitly rejects a second scene.Render before encoding. `SetCacheXform` captures that current view/projection. If Root elects one existing-toggle diagnostic anyway, require correct `before/eligible/exempt/unknown/removed/remaining` counters, no complete-group witness bypass, current qualified shader inputs, completed same-frame admission and useful matched caster/draw reductions. A full performance/visual claim still needs same-binary accumulator/combine/scene raw pixels and motion through face/near-plane/eye-inside boundaries. This review recommends stopping based on the prior small removal signal; no such run is requested here.
