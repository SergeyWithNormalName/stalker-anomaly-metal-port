# Review: indoor07 LMH source-family opportunity census

**Assessment: conditional pass as a source-family upper bound.** I found no arithmetic or input-integrity defect that invalidates the 908/1,205 census count. It remains an upper bound over a broad source-family classifier, not a count of actual admitted LMH draws or demonstrated suppressible draws.

The input gates pin the active level and `level.geom` hashes, frame 700, start sector 25, full-transform source-order match, live view match, no suppression, and a separate runtime validator. That validator passed all 45 checks, including exact view/projection/eye/SSA assertions, active-reader byte/hash checks, graph reachability (six nonempty sectors/eight frusta), and Flora observer receipt consistency. The Flora ID assertions qualify the frame receipt; they are not used as the LMH draw inventory.

The emitter's broad classifier is `shader.textures[2]` starting with `lmap`. The production selector is narrower: `visual.valid`, indexed bounds, default or allowed `def_aref` shader, exactly three textures with both light-map suffixes, exact vertex ABI, and successful texture resolution (`MetalR4EngineScene.mm`, `selectAutomaticLmhMaterials`). Therefore the broad set can overcount potential LMH opportunities; the report correctly does not call its rows actual draws. All 2,185 emitted source rows have available indexed-position bounds, valid OGF bounds, and known owners in this fixture.

For each candidate, ordinary camera rejection tests all eight indexed-bounds corners against the six Metal clip planes. Portal rejection transforms the local bounds' eight corners into a world AABB, then uses the negative support point for each captured `CFrustum` plane; this is a conservative superset of transformed geometry. A candidate is retained if any frustum of any owner intersects. The formula matches `CFrustum::AABB_OverlapPlane` in `src/xrCDB/Frustum.h` and its sign remap in `src/xrCDB/Frustum.cpp`; unknown owners/bounds fail open.

I checked the reported rejects using float32-style arithmetic on the round-tripped source bounds/model values and captured plane/full-transform values. All 980 camera rejects remained outside; the closest rejected camera plane had about `1.22e-4` separation after float32 evaluation. All 908 portal rejects still rejected across every owner/frustum; the smallest positive plane rejection was about `3.73e-3`. These margins are larger than the script's `2e-5` fail-open tolerance. This check supports the offline arithmetic but does not replace a same-frame GPU image oracle.

The material limitation is explicit and important: the 2,185 `lmap*` source visuals are not joined to the runtime `textureMaterialByVisual`/pipeline-admitted draw list. In particular, the 1,147 telemetry sample is not frame-aligned and must not scale the 908 count. The census does not prove that any particular ID was submitted in the measured frame, that skipping it preserves pixels, or that a Windows path would agree. Treat 908 as the maximum source-family opportunity indicated by these pinned inputs, not an expected draw reduction or performance estimate.
