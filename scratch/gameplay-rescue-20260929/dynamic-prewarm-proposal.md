# Dynamic world follow-up: prepared owner, freshness, and needed work

Read-only source audit after V2 source freeze. No production edits or hardware tests. Audited sources: DynamicWorldAdapter CPP SHA256 `c16124a0fea5024896c3450fb2fd455f51791f7219b52789c74bfc86be6e151a`; EngineScene SHA256 `39a0b51b08e3c161a2528bf2d4be6a40e39cf3bcd2e1c854a858ec5a4debcc20`.

## Existing dynamic BVH guard reaches production

`MetalRenderDeviceRender.mm:1266` is the only production `SubmitEngineWorldRenderables` caller. Backend creates and publishes one shared immutable world owner (`MetalR4Backend.mm:2544–2595`), and its getter returns that same shared pointer under a lock. Publication precedes `scene.Render` at device-render line1540. `MetalR4EngineScene::Render` Prewarm at line6879 uses that owner; its production sun draws at line3945 and local atlas tiles at line3055 fetch the same owner. No production call republishes it during Render. The slot is assigned in BeginFrame at backend line1207 and does not change until after scene encoding. Thus successful Prewarm's pointer/frame/slot checks match ordinary sun/local draws; the guard is not structurally forced into linear fallback.

Prewarm invalidates the retained owner before early failures and publishes only at successful end. A retry calls Prewarm again and rebuilds for its current acquired slot. The temporal multi-view diagnostic rejects its second primary Render before Prewarm, so it cannot replace the index midway. The outside-NPC witness constructs a different shared world at EngineScene line4672 and intentionally uses fallback on the production adapter. Its separate `coldDynamic` producer Prewarms its own `outsideWorld`, so that producer can index its matching witness. Runtime qualification must still show `indexed_views > 0`; a zero-miss fallback-only log is insufficient.

## Concrete stale-instance source path

`CachedInstance` has retained pose/uniform buffers and `lastUsedGeneration`, but no prepared owner or current Prewarm epoch. Instance identity is geometry content plus CObject ID (or snapshot ordinal) plus acquired slot. Three slots are retained, with unused instances pruned only after180 engine-frame generations.

At Prewarm entry `DiscardUnsubmittedFrame` clears pending motion only. An outside-main renderable with `castsShadow=false` returns `Skip` at line2175–2180. An outside-main non-skinned caster returns `ShadowGeometryOnly` at line2303–2306. Neither path clears an existing same-slot instance. Current pose validation can also fail and continue while an old instance remains. G-buffer `Draw` at line2687–2693 accepts any found instance and uses its old transforms/pose; it checks neither freshness nor camera frustum. Emissive at line2883 and sorted lightplane preparation at line2986 have the same lookup-only admission. Skinned shadow drawing at line3137 accepts any found skin buffer.

This is reachable through production capture: `r_dsgraph_capture_metal_world` queries shadow volumes with `STYPE_RENDERABLE | STYPE_RENDERABLESHADOW`, renders all nonparticle candidates, and `capture_metal_world_renderable` separately sets `castsShadow` from `renderable_ShadowGenerate`, inherited shadow permission and `eNoShadow`. A non-shadow child/object captured near a light or sun volume can remain in the world snapshot after leaving the main view. If an older slot already holds its instance, Prewarm skips it but Draw can consume the previous slot's transform. This establishes a stale-state path in source; it does not establish how frequently it occurs in the canonical save or its measured pixel impact.

Bounded repair proposal after scope review: introduce a monotonically advancing Prewarm invocation epoch, independent of engine frame and acquired slot. Clear/advance at every Prewarm entry, including early failure; stamp each instance only when the current route's required buffers have been successfully prepared. Every G-buffer/emissive/lightplane consumer must require current main-instance readiness. Skinned shadow consumers separately require current skin readiness, permitting later shadow-only preparation without unnecessary main uniforms. Static shadow geometry continues using immutable cached geometry. Pose-hash reuse is valid only after current snapshot pose was checked; it can stamp readiness without recomputing the unchanged skin. Retained cache data remains available for reuse but cannot itself confer draw admission.

Regression gate should drive actual Prewarm/Draw paths with a recording backend: prepare A visible in slot0, revisit slot0 with A outside and no-shadow, assert no old-transform draw; repeat with static ShadowGeometryOnly, missing/invalid current bones, a repeated engine frame with changed snapshot owner, and early-failed Prewarm. Positive controls: an unchanged current pose reuses its existing buffer and draws; a current off-camera skin required by a light still casts its shadow; a frame retry re-prepares its acquired slot. Source-only tests of a separate stamp helper would not prove consumers enforce the contract. GPU/scene screen remains separate.

## Authorized readiness draft, held outside production

Root authorized a narrow readiness fix; draft lives only under `dynamic-epoch-draft/` until runtime lead confirms V2 copied. `dynamic-cpp.diff` shows the change against the current frozen CPP. A new shared `R4DynamicWorldPreparedState.h` contains the unchanged Prewarm disposition classifier, unique invocation epoch, completed-Prewarm gate and per-instance `mainPreparedEpoch`/`skinPreparedEpoch`. A current successful pose reuse or skin upload publishes skin readiness. A current successful main UBO preparation publishes main readiness unconditionally. All instance consumers require current readiness and completed Prewarm; immutable static shadow geometry remains unchanged. Commit/Discard motion behavior is unchanged.

The draft deliberately preserves fully prepared off-camera skinned main draws. It does **not** turn the old sphere predicate into a new camera cull. The earlier proposed `PublishMain(epoch, mainViewVisible)` was rejected in review and removed. Actual Skip/ShadowGeometryOnly already exit before main instance publication; the epoch prevents those routes from reviving retained old state.

The touched pre-existing uniform-update failure at original CPP line2563 erases `existing`, then the CPU diagnostic branch at line2567 compares and may dereference that invalid iterator. Draft sets it to `instances.end()` immediately after erase. The recording-backend error-path test is not available in the existing CPU probe; no hardware fault injection was run during V2 build.

Persistent shared-foundation probe draft uses the actual disposition classifier and state machine for slot wrap, skipped non-shadow, static shadow-only, current off-camera skin positive control, invalid current pose, repeated simulation frame/drawable retry, early/late failure, and rollover. Draft runner `script/test_dynamic_prepared_state.sh` compiles optimized and UBSan configurations. No probe execution or gameplay qualification is claimed yet. Test registration can be copied after V2 freeze with the source; compute integration must reuse this epoch, and its successful-submit journal commit remains a separate lifecycle event.

## Needed-work proposal and safety gate

Current Prewarm prepares all skinned shadowcasters even if no surviving local face or sun cascade admits them. Once real local batch planning is moved before Prewarm, a needed set could be the union of main-view contribution plus exact current shadow-view admission, then skin only that set. Use the same retained world owner, immutable lighting/environment snapshots and actual encoded matrices; compute the plan once and consume it later rather than reproducing planner decisions. Local matrix construction currently lives at EngineScene lines2815–2820; sun matrices are already installed by updateSceneView before Prewarm. Frame-plan validity must include world/lighting owners, selected camera/environment and acquired slot. Any incomplete or invalid plan falls back to the existing full preparation, and diagnostics needing extra witness views either declare them or bypass the pruning.

However the old sphere is insufficient to prove main-view pixel safety. Shadow draws already use that exact old predicate, so it defines shadow need without new omissions. G-buffer, emissive and lightplane consumers do not cull the main view and may render animated geometry outside its visual sphere. Existing skin sanity allows `max(64m,32×expectedRadius)`; it is not an enclosing bound and must not be tightened for this optimization. Simply skipping objects because the old sphere is outside would change current rendering.

First safe structural step: preserve exact CPU skin output bounds in each instance while it is already produced. After successful skinning, a conservative per-pass test of the actual deformed position AABB can skip G-buffer/emissive/lightplane binds and draws while retaining shadow skin resources. This saves encoding work, not the current skin CPU cost. Prove that each admitted shader's vertex position uses only that packed SKIN_0 position with affine transforms; any extrusion/unknown shader family retains old draws. Bounds must match the current pose and owner/epoch; reuse requires a matching cached pose. Invalid/nonfinite bounds fail open. Pixel parity must include animated moving models and special families.

To avoid skinning entirely, prepare immutable per-bone source contribution envelopes and transform them conservatively for the current pose before skinning. 2W weights may be outside[0,1], and 3W/4W residuals are intentionally signed; a convex union of transformed bone boxes is not generally sufficient. Use signed interval contributions plus outward rounding, with CPU fallback for unqualified format/data. Visibility architecture owns the compute foundation; the current foundation decodes the exact signed weights but does not yet implement envelopes. No additional backend/GPU rewrite is proposed here.

Observe-only gate before implementation: report currently changed-pose vertices and bytes for the full set versus safe needed set, views/owners/slot, exemptions/fallbacks, and exact-list oracle violations. Saved heavy evidence (roughly459 objects×303 views) establishes repeated cull opportunity, not milliseconds from this new candidate. Do not claim an FPS gain until central same-binary A/B and completed pixel/motion proof.
