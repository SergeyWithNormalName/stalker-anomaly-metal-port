# CPU coverage observation wiring

This is a design note only. It does not change the frozen retention/admission draft, draw order, or visibility decisions. The next stage remains opt-in and observe-only; native pixel orientation and CPU/Metal coverage equivalence are still unqualified until the offscreen probe passes.

Build the static coverage grid once per begun observation scope, only when the current scene selected at least one complete eligible shadowed group. Run it after main G-buffer production and after visibility-group selection, immediately before local-shadow/accumulation batch processing. Feed only retained triangles whose successful main-G-buffer draw receipt matches the current `scopeId` and `engineFrame`; the static-motion replay is excluded. For each retained local `POSITION0` vertex, evaluate the exact stamped `uploadedWvp` and the admitted flat VS jitter operation `hpos.xy + uploadedJitter.xy * hpos.w`. Compute each row's absolute dot-term sum in double and round its float bound upward; pass that as `clipAbsDotTerms`. Keep arithmetic strict (no fast-math), include a conservative binary32 dot bound and underflow/FTZ allowance, and bound the jitter multiply/add separately in `upstreamAbsError` (cover both fused and unfused execution). Reject non-finite/unbounded inputs as unknown. The frozen qualified `deffer_base_lmh_flat.vs` uses this clip-jitter operation; the staged receipt currently captures exact zero jitter, but consumers must use captured bytes rather than assume zero (`source-admission.md`, “Active V5 shader-source verification”; `R4ActiveOcclusionCoverage.h`, `ClipVertex`).

Do not reuse the static transform for local-light queries. The actual local-volume VS is `accum_volume.vs:11-18`: it computes `mul(m_WVP, P)` for clip position and has no clip-space TAA-jitter operation; `USE_SJITTER`, when enabled, affects only `tcJ`. The adapter builds `model = localLightModel(light)` and `wvp = (projection * view) * model`, uploads that WVP to vertex transforms at offset 0, and uploads `viewProjection = projection * view` to fragment globals at offset 64 (`MetalR4LocalLightAdapter.cpp:469-491`). `BuildMetalR4LocalLightVolumeBounds` returns a padded **world-space** AABB around the actual point/spot/omni-part volume, including `.01 + 1e-5 * maxAbs` padding (`MetalR4LocalLightAdapter.cpp:629-687`). Use its eight world-space corners with the exact uploaded `viewProjection` bytes for `QueryPaddedAabb`; do not pass the local-space `wvp` to world-space corners. Bound the CPU projection's dot/jitter/FTZ arithmetic as above (jitter is absent for this shader). If the chosen runtime artifact/permutation changes the clip path, matrix contract, or depth convention, skip that query. The existing volume bounds are deliberately conservative; no alternate sphere or tighter shape should be introduced here.

For each selected `R4WholeLightVisibilitySample`, run a CPU query only if its full spot record or all six omni faces are selected and valid, the current observation scope has a complete grid, and the sample's engine frame/batch/light identity still matches the captured snapshot. Query the corresponding light's `BuildMetalR4LocalLightVolumeBounds` corners and store only an observe-only prediction (`ConservativelyBehindCoverage` or visible/unknown) keyed by `(cpuObservationScopeId, engineFrame, batchId, lightId, parentLightId, face)`. Set that exact nonzero scope ID on the tagged final accumulation draw; legacy GPU-only samples retain zero. Do not query unshadowed lights or infer a whole-light result from one omni face. The sample selection/face batching and the actual accumulation draw are in `MetalR4EngineScene.mm` near `SelectR4WholeLightVisibilitySamples` and the `accumulate` lambda; the adapter tags only the final accumulation draw (`MetalR4LocalLightAdapter.cpp:574-622`).

Join CPU predictions only to completion-owned GPU face/group receipts using the full tuple including `cpuObservationScopeId`. A zero GPU count is a `zero_deferred_receiver_samples` receipt, not proof that the light is invisible or contributes nothing elsewhere. Missing, aborted, invalid, incomplete, mismatched-scope, or duplicate receipts stay unknown; never treat absent completion as zero. Report per-face CPU prediction beside actual completion count, then group only when all expected faces have both records. Keep this sidecar bounded to the existing selected-group/frame caps. No CPU result may suppress a batch, draw, shadow tile, or alter any shader or stencil/depth operation.

Remaining gates: native probe must establish Metal viewport Y direction, pixel-area/winding convention, depth mapping, and a conservative edge/error margin for both the admitted static VS and the local-volume query projection. The latter uses a different vertex path and must be calibrated independently. Until then, observations are diagnostic only and should be labeled unqualified/inconclusive.
