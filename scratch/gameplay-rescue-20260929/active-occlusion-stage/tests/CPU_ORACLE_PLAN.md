# Active-geometry coverage: independent CPU oracle plan

Scope: scratch-only CPU correctness proof for the default-off 64x64 conservative coverage/query helper. No game, GPU, production source, or CMake work. This oracle is independent of the helper's cell-coverage implementation and must be reviewed with the helper API before compilation.

## Oracle/reference separation

- Feed the helper its normal projected-triangle and query-rectangle inputs. Do not inspect or reuse helper edge functions, cell masks, tile loops, projected-union output, or depth aggregation to decide reference coverage.
- Independently rasterize the original, unmerged projected triangles at full 128×128 fixture resolution (not a 1920×1200 native-render-resolution proof) using double-precision barycentric edge equations, pixel-center samples, and a separately implemented top-left ownership rule in explicit logical pixel coordinates (x right, y down). Do not infer screen-area winding from clip-Y mapping: use the API's separate explicit pixel-area winding convention, and label native orientation unqualified unless its caller convention is independently verified. Interpolate the renderer's post-projection depth independently at each covered sample; for normal depth, the frontmost opaque reference depth is the minimum covering depth. For triangles sharing an edge, test both submission orders and winding-normalized inputs; a sample on the common edge must have deterministic ownership, never a hole caused by enumeration order.
- A `ConservativelyBehindCoverage` query result is acceptable only if every full-resolution pixel-center sample in its query rectangle has reference opaque coverage, and the reference frontmost depth (minimum depth among overlapping opaque triangles under the selected normal-depth convention) is strictly in front of the query's outward-conservative nearest depth by the API's declared comparison rule. Do not inspect private grid state; exercise it through the public padded-AABB query API. Boundary equality or insufficient margin means visible.
- Also test a deterministic 4x4 subpixel lattice per full-resolution pixel only in the adversarial edge/seam cases. This is an added conservatism check for thin cracks; pixel-center reference remains the primary comparison to the renderer's sampling convention. Preserve exact original triangles in the reference, even when the candidate optionally uses an adjacent-triangle projected union.

## Bounded cases

1. Positive witnesses: require a query fully inside a single unpaired triangle to return hidden, and require a query crossing an exact reciprocal adjacent pair's shared seam to return hidden with `pairedUnionsAccepted > 0`. Exercise the same pair in reversed submission order and reversed vertex winding. These are logical fixture conventions, not proof of native Metal front-face equivalence.
2. Negative space and pair rejection: four-bar window, subpixel gap at a mismatched shared clip seam, and a query partly covered by one triangle. Every hidden result must still pass the independent sample oracle; mismatched pairs must be rejected and the gap query must remain visible.
3. Depth/error: foreground object, exact depth equality, and a sloped depth crossing within the query rectangle. A positive interior case uses non-unit W and nonzero upstream error bounds; eight shared-vertex-consistent signed perturbation patterns of original clip vertices must all remain reference-covered and strictly in front of the query.
4. Fail-open/view lifecycle: nonopaque or non-guaranteed stencil input, invalid vertex W/depth, invalid query corner, zero or mismatched observation scope, viewport/Y mismatch, unknown pixel-area winding, and query wholly outside the view. Fresh translated and resized fixtures use new scopes. Query visits must remain `<= kMaxQueryCellTests`; with one visit per clamped grid cell and `kMaxQueryCellTests == 4096`, the public query path is structurally bounded by the grid, so do not add a test seam merely to force its cap branch.
5. Build caps: exceed the triangle cap and primitive cell-test budget after establishing a small known-safe prefix. Verify prefix queries can remain hidden while regions outside retained proven coverage remain visible. No claim that capacity exhaustion invalidates already-proven coverage.
6. Deterministic mixed suite: 64 fixed-seed bounded triangle/query arrangements combining coverage, gaps, and depth relationships. This supplements the named regressions; it is not a fuzzer or native-resolution proof.

## Acceptance and evidence

For every case record the input, helper status/cells/depths, independent pixel-center coverage count, independent nearest opaque depth for every reference sample and query-depth margin, and verdict. Require at least one hidden single-triangle witness and one hidden paired-seam witness that reports an accepted union. Any helper-hidden rectangle with a single uncovered reference sample, invalid sample, or failing depth comparison is a hard failure. Visible results when fully covered are conservative false-visible outcomes and should be counted separately, never failed as correctness. Record whether a failure is fail-open due to an advertised cap/state or a false-hidden result. No aggregate pass may conceal a named regression.

The backend header defines post-WVP/post-jitter clip vertices, explicit conservative error terms, separate viewport-Y mapping and pixel-area winding, frontface/cull/depth/stencil/opaque state, and a positive raster-edge guard; these are inputs, not proof that the arithmetic model matches Metal. Bind tests to the exact API semantics and draft one standalone C++ probe under this directory. Wait for root review of both the source and exact compile command before any compile/run. No CMake registration or production-source change is part of this task.
