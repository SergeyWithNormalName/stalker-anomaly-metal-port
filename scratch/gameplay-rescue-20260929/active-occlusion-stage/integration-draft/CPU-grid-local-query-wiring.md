# Active-occlusion CPU grid/query draft

Scratch integration only; no suppression is connected. The frozen retention inputs and their manifest are copied verbatim under `prestate/`. This stage uses the measured synthetic convention (clip +Y maps to lower pixel rows, positive pixel area is clockwise, one-pixel edge guard) but labels every summary `raster_convention=synthetic_only suppression=disabled`. The M1 Pro probe covered 20 synthetic cases at 128x128 and 1920x1200; it does not prove runtime scene equivalence.

When both `XRAY_METAL_ACTIVE_OCCLUSION=1` and the existing whole-light visibility selection are enabled, the scene selects complete shadowed groups first. Only then, after the main G-buffer pass and before local shadow/accumulation batches, it builds one 64x64 coverage grid from retained triangles whose actual main-pass draw receipt matches the current nonzero observation scope and engine frame. The static-motion replay is not admitted. Retained per-visual exact reciprocal shared-edge mate IDs are built once during source extraction from indexed UInt16 triangles, before geometry bytes are cleared. They are translated to each draw's local triangle span; there is no per-frame edge hash or all-pairs search. The per-frame triangle vector is bounded to 32,768 before appending; skipped draws and caps are reported. The foundation may stop at its primitive-cell budget while preserving only proven coverage.

`R4ActiveOcclusionSceneBridge.cpp` is a dedicated strict-FP unit. For each source `POSITION0`, it evaluates the captured float WVP in column-major row-dot order with a fixed fused CPU representative, and applies the captured flat-VS jitter as `fma(jitter, clip.w, clip.xy)`. The absolute four-product term sum is accumulated outward in double and rounded upward to float. The foundation adds its GPU-side `gamma8` dot bound and `8*FLT_MIN` underflow allowance; the bridge adds a corresponding CPU-side dot bound. For jittered XY it also bounds both CPU/GPU W-dot error propagation by `|jitter|`, fused or unfused multiply-add rounding, and FTZ. Non-finite or unrepresentable inputs fail open. Exact uploaded matrices/jitter are used; no camera values are reconstructed.

For each selected face, the query uses the existing padded world AABB from `BuildMetalR4LocalLightVolumeBounds`. `accum_volume.vs` clips local positions with `W*P`; it does not apply clip-space TAA jitter. The adapter now has a pure `BuildMetalR4LocalLightCameraViewProjection` that runs the existing `multiply(projection,view)` implementation, and the ordinary upload path consumes those same bytes. Shared model/WVP helpers also preserve the adapter's existing `localLightModel` and multiply order; while the observer flag is off, the original compact per-light model/WVP path remains in use. The query projects the world-space AABB with that same camera VP, not the local `VP*model` matrix.

The remaining numerical gap is explicit. A world AABB projected by `A` is not bitwise the same path as the shader's `(A*M)*P`. The bridge bounds `A*M` component error as `E_W[r,j] = gamma8 * sum_k |A[r,k] M[k,j]| + 8*FLT_MIN`, outward-rounded. With actual canonical local-mesh `pmax`, it bounds association by `E_assoc[r] = gamma8 * sum_j |W[r,j]| pmax[j] + 8*FLT_MIN + sum_j pmax[j] E_W[r,j]`, also outward-rounded. That term is added to (not substituted for) the CPU camera-VP corner error in each query corner's `upstreamAbsError`. `A`, `M`, and `W` come from the same helpers used to construct the adapter upload values. The existing `.01 + 1e-5*maxAbs` world-bound pad remains in force. This is a conservative diagnostic bound, not a production equivalence certificate; unsupported matrices/vertices/corners yield `visible_or_unknown`.

The local-volume VS is qualified only when the active `accum_volume.vs.metallib` and reflection hashes match the pinned runtime artifact and the bounded `local-lights-msc-receipt.txt` matches its pinned source-tree/compiler/entry/define/output identity. Unknown or changed bundles skip the CPU query; GPU-only visibility observation can still proceed. Face samples are matched against the current snapshot, exact batch membership, group kind, expected face count, light/parent/face, frame, and scope. Scope IDs are copied onto samples before the existing `DrawState` copy. One omni face never stands for its six-face parent.

Every selected face gets one `METAL_ACTIVE_OCCLUSION_FACE` row with `cpu_observation_scope`, `engine_frame`, `batch_id`, `light_id`, `parent_light_id`, `face`, `group_kind`, `expected_faces`, `prediction=behind|visible_or_unknown|unknown`, `query_cells`, and a reason token. One final `METAL_ACTIVE_OCCLUSION_GRID` row per active observation frame reports selected groups/faces, draw/triangle/pair counts, marked cells, primitive/query cell tests, invalid/cap flags, and `build_ms`/`query_ms`. `build_ms` includes source conversion, transformed clip vertices and grid build; `query_ms` includes all selected bounds/corner/query work and the FACE diagnostic writes. The bounded 12-scope / 8-group / 48-face limits remain. Backend completion face/group receipts join only by scope, engine frame, batch, light, parent, face, group kind and expected-face metadata. Missing, aborted, invalid, or mismatched results remain unknown; `zero_deferred_receiver_samples` is not an invisibility claim. No prediction changes batches, draws, shaders, order, depth/stencil, culling, or pixels.
