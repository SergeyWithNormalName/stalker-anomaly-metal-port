# Adapter oracle stage plan

Scope: `src/Layers/xrRenderMetal/MetalR4DynamicWorldAdapter.cpp` only. Backend owns `R4ComputeSkinOracleRequest` and `R4ComputeSkinJob::oracle`; adapter changes wait for that exact descriptor to appear.

- Strict independent opt-in `XRAY_METAL_COMPUTE_SKIN_ORACLE=1`, in addition to existing compute opt-in. Default-off path performs no reference repack or expected-byte allocation.
- Select at most one eligible changed-pose job per Prewarm. Only influence classes 1–4 with committed count below two are selectable. Skip expected streams larger than 4 MiB and continue searching later classes.
- The selected reference is generated by the existing full CPU `repackR4DynamicWorldSkinnedVertices` from that exact raw source/palette. Own all `vertexCount * sizeof(R4DynamicWorldSkinnedVertex)` bytes. Attach stable instance key, pose hash, output write serial, current Prewarm epoch, and world engine frame. Any reference failure or size mismatch leaves the GPU route unproven and the request absent; no relaxed comparison.
- Store selected class only after successful `EncodeComputeSkinJobs` and only for requests still present in the final deduplicated job vector. Do not count rejected batches.
- Increment the per-class quota only in `CommitSubmittedSkin`, after successful frame submission. Clear pending classes in `DiscardUnsubmittedFrame`; late-submit retries do not consume quota. A one-request-per-frame limit gives distinct submitted frame serials.
- No GPU/build/test execution from this agent. Runtime owner runs the authorized focused wiring/mock validation after source freeze.
