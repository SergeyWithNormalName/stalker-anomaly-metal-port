# Candidate V5 compute-skin integration plan

No production adapter routing, application build, or game run is included in this plan. Current proof is standalone only: CPU bounds/random coverage passes, the Metal backend API probe and upload lifecycle tests passed 3/3, and the arithmetic oracle still builds and links after Foundation moved into the backend library. The arithmetic GPU test was not rerun. The API probe manually acquires an internal frame and validates the shared epoch helper; its retry/slot-wrap case does not drive real `BeginFrame`/`SubmitFrame` behavior.

1. **Wire one opt-in production route.** Keep `XRAY_METAL_COMPUTE_SKIN` disabled by default and leave all unsupported geometry on the existing CPU repack path. Admit only canonical decoded input whose complete-batch resources, bone slices, bounds, and acquired-context epoch pass; reject aliased or stale slices before any writes. Encode after pending Private uploads on the acquired frame command buffer, end compute before graphics consumes the output, and keep resources alive through command completion. Commit prepared pose/history state only after successful submit; discard or drawable retry must release pending state and permit a clean retry.

2. **Add focused integration gates before linking V5.** Exercise supported 1–4 influence formats and the installed content corpus. Require bitwise equality for every byte of the 36-byte CPU/GPU output record, including positions, packed basis, UV, and alpha; introduce no position tolerance without separate evidence and root review. Also verify conservative bounds and unchanged existing radius guards. Prove ineligible/tangent-rebuild inputs use CPU fallback, rejected batches preserve output sentinels, and upload/context retry, discard, completion, and slot wrap use actual backend entry points. Keep the 512-case CPU bounds probe, arithmetic GPU oracle, backend API contract probe, and FrameUpload/PrivateUpload regressions as separate evidence.

3. **Build an isolated candidate app after source review.** Link only to a new V5 candidate path, record source/app hashes, and preserve V4 (`2bb3dc6b…`) and the original app (`b0bcf586…`). Clone the normal V4 GAMMA runtime once into a fresh V5 run path, keeping installed archive symlinks and the original profile/save untouched. Set the compute switch only for the candidate run; do not modify shared renderer defaults, installed mods, or package/redistribute the mod collection.

4. **Validate correctness before measuring economics.** After the user unlocks the desktop, run a short live correctness pass on the same saved world with AI and simulation active. Use actual NPC/animated geometry, controlled weather and resolution, production fallback counters, GPU output/oracle results, and on-screen captures during camera and world motion. Check Metal/API diagnostics and frame-resource ownership. If any output, counter, or visual gate fails, turn off compute for that content and repair before continuing. The API probes alone do not satisfy these runtime gates.

5. **Screen performance with one binary and matched state.** Only after motion correctness passes, compare compute off/on within the same V5 executable using fresh clones of the same save/config, identical environment, and ordinary uninstrumented windows. Keep correctness/profiling counters off during timing. Report wall callback rate separately from presented cadence and CPU/GPU work; repeat matched pairs only if the initial screen shows a clear, consistent change. A small synthetic dispatch win or a stationary scene does not establish gameplay improvement.
