# Static G-buffer admission contract for a future current-frame CPU occlusion candidate

Source snapshot: V5 production renderer in this working tree, audited 2026-09-29. This is source evidence for a possible opt-in optimization, not proof that CPU coverage equals Metal rasterization. It does not authorize suppression. The existing whole-light result is only a deferred-accumulation sample; static geometry is an independent candidate source.

## Narrow candidate class

Start with the `MetalR4EngineScene` production MSC `LevelScene` path only, and only `R4StaticVisual`s which are admitted through `scene.textureMaterialByVisual`, use the qualified opaque `default` / `deffer_base_lmh_flat` shader pair, are not AREF, and are not tree visual types 7 or 11. Require the exact already-qualified shader artifact/semantic receipt, vertex ABI, resources, transforms, and draw state. The runtime currently validates bundle artifact hashes against `lmh-msc-receipt.txt` (`MetalBootstrap.mm:779-844`); this proves bundle/receipt consistency, not that a mod update preserved old shader semantics. Thus the candidate must be keyed to the previously qualified artifact/source/defines identity. An unknown or changed bundle/source disables only this optimization and falls back to ordinary rendering.

The source `deffer_base_lmh_flat.vs` includes `deffer_base_flat.vs`; that VS computes `m_WVP * I.P`, then applies `ssfx_taa_jitter` to clip XY (`scratch/water-next-source/deffer_base_lmh_flat.vs:1-2`, `deffer_base_flat.vs:19-20,32-33`, `screenspace_mvectors.h:21-26`). The flat PS samples diffuse RGB but has no alpha discard (`deffer_base_lmh_flat.ps:1-2`, `deffer_base_flat.ps:10-35`). Exclude `_d` displacement shaders, AREF/alpha-tested materials, vegetation/wind/grass/flora, terrain, HUD/scope, dynamic visuals, custom or unknown shader families. Also fail open for non-finite inputs, unsupported raster state, or any semantic/artifact mismatch.

## Geometry and draw admission

`R4StaticVisual` provides visual type/id, VB/IB ids, `vertexBase/count`, `indexBase/count`, validity, model transform, and parser-computed referenced position bounds (`R4LevelGeometry.h:46-73`). The parser requires POSITION0 Float3 and derives stride from the stream-0 declaration (`R4LevelGeometry.cpp:240-283`). Its bounds loop reads each UInt16 local index from `indexBase + i`, rejects an index `>= vertexCount`, then reads POSITION0 at `vertexBase + localIndex` and rejects non-finite/truncated positions (`R4LevelGeometry.cpp:380-432`). GPU draw parameters match that representation: UInt16, byte offset `indexBase * 2`, `indexCount`, and `baseVertex=vertexBase` (`MetalBootstrap.mm:3514-3520`). The CPU copy must use checked arithmetic and those exact origins, not reinterpret index values as global indices.

`prepareLevelScene` admits only resolved material inputs whose visual exists, is valid, has referenced bounds and a valid shader, and whose supplied base texture matches the parsed shader (`MetalBootstrap.mm:1297-1317`); it records parsed shader name and model transform on `TextureMaterial` (`1408-1415`). Engine production requires the production MSC bundle, base lighting, sun, luminance, and complete admitted material count (`MetalR4EngineScene.mm:6192-6205`). A material-set membership check alone is insufficient: `drawLevelScene` also requires valid visual/bounds, an available pipeline, membership when texture materials are active, optional live-frustum admission, successful resource binding, and successful `DrawIndexed` (`MetalBootstrap.mm:3406-3521`). The narrow receipt point is immediately after that draw succeeds; this records actually submitted visuals without reordering draws or confusing skipped/failed visuals with occluders.

The production MSC transforms are refreshed per frame as `viewProjection * modelTransform` (`MetalR4EngineScene.mm:2312-2325`). The LevelScene pipeline has depth compare `Less`, depth writes enabled, and under the production material path back-face culling with clockwise front faces (`MetalBootstrap.mm:1655-1673`; `textureDiagnostic` is true for explicit material inputs at `MetalBootstrap.mm:1165-1167`). The source comment explicitly ties this to R4's D3DCULL_CCW convention. Native pipeline setup maps that winding to Metal (`MetalR4Backend.mm:772-775, 2798-2806`). A CPU raster must conservatively honor front-face/cull semantics; treating both windings as covered can falsely occlude. Default native viewport is full attachment with depth range 0..1 (`MetalR4Backend.mm:1681-1683`); preserve clip-to-viewport orientation and the per-frame TAA jitter rather than assuming an unjittered camera projection.

`geometryBytes` is uploaded into private vertex/index buffers in `uploadLevelScene`, and `commitLevelSceneUploads` clears and shrinks the CPU geometry bytes after successful upload (`MetalBootstrap.mm:2914-2933, 3028-3048`). Therefore, if CPU triangle inputs are to survive warm frames, copy only bounded, eligible indexed POSITION0 data/metadata after geometry/material validation and before the upload commit clears the source. Do not retain the whole level blob. Continue to record current-frame actual draw admission after resource binding and `DrawIndexed` succeeds; a retained mesh is not evidence it rendered this frame.

## Depth/stencil continuity through local accumulation

The main G-buffer pass begins with the depth attachment's default `Clear` action and clear depth 1.0, then stores it (`IR4Backend.h:148-156`; `MetalR4EngineScene.mm:4142-4157`). Production static and other world G-buffer producers all draw before the pass ends: def-vertex, def-objects LOD, terrain, and scene-owned world callback follow `drawLevelScene` (`MetalR4EngineScene.mm:4154-4212`). Those omitted families can add nearer depth, so excluding them is conservative (less estimated occlusion), provided the candidate only treats its own proven static depth as occluding.

After G-buffer, the optional static-motion probe renders into separate probe color/depth targets and clears those targets; it does not mutate `scene.depthTarget` (`MetalR4EngineScene.mm:3747-3802`). Color-capture calls receive only G-buffer color textures (`4212-4218`), not main depth. HUD/scope near-depth uses main depth Load/Store and a 0..0.02 viewport; it can add nearer HUD depth (`4240-4274`). The scope zwrite pass also Load/Stores depth and writes the saved pre-HUD world depth from `scopeDepthSnapshot` under scope stencil, restoring world depth in its mask rather than introducing arbitrary farther depth (`4276-4303`; `MetalR4ScopeAdapter.cpp:149-172,469-479`; `scratch/water-next-source/models_scope_zwrite.ps:1-20`).

The accumulator clear has no depth attachment (`MetalR4EngineScene.mm:4392-4400`). Direct-sun mask/cascade passes use main depth/stencil Load/Store; their pipeline depth writes default off, and the sunlight changes stencil/accumulator state, not depth (`MetalR4EngineScene.mm:4402-4411,4458-4462`; `MetalBootstrap.mm:2106-2157`). Emissive accumulation passes Load/Store main depth; its producers are not static depth occluders (`MetalR4EngineScene.mm:4490-4525`). Each local-light accumulator batch likewise Load/Stores the same depth and stencil (`4527-4541`), and the local-light accumulation pipeline explicitly disables depth writes (`MetalR4LocalLightAdapter.cpp:298-307`). The per-batch shadow atlas has its own depth attachment; it is not the scene depth (`MetalR4EngineScene.mm:4664-4674`). I found no depth clear/reset between the G-buffer and local accumulation. Stencil is intentionally mutated by sun/scope/local-volume work; any future candidate must not mistake stencil changes for depth changes or depend on G-buffer stencil remaining original.

## Remaining proof boundary

This audit establishes a safe place to build a bounded candidate set and a source-side depth lifetime. It does not establish exact CPU-vs-Metal pixel coverage, clip/raster rounding, front-face sign under every admitted transform, visibility across missing non-static passes, or shader semantic equivalence after mod updates. The candidate should initially be observe-only, report per-frame eligible and actually admitted IDs, and fail open on any unknown; no draw rejection is justified by this note.
