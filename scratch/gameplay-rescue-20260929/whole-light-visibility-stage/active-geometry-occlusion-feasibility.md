# Active geometry occlusion feasibility

Source context: `<XRAY_SOURCE_ROOT>`, working-tree snapshot inspected on 2026-09-29. This checkout contains unrelated dirty WIP; line references below are to the inspected working-tree files, not a clean commit. This is a read-only architecture note. It reports no new build, game run, performance measurement, or savings claim.

`CHOM::RenderDiagnostic` is not a trusted geometry source for this experiment. `CHOM::Load(false)` opens `$level$/level.hom` (`src/Layers/xrRender/HOM.cpp:85-105`) and explicitly reports `geometry_verified=0`; the active level and `level.geom` can come from the mod. The existing raster is global and non-reentrant: it uses `Raster`, plus file-static triangle state in `src/Layers/xrRender/occRasterizer_core.cpp`. Its `propagade()` pass synthesizes depth between nearby shared-triangle samples (`src/Layers/xrRender/occRasterizer.cpp:82-137`), and the scan converter extends edge coverage with connectors and center/far-depth adjustments (`src/Layers/xrRender/occRasterizer_core.cpp:145-167`). Those semantics are not qualified for a no-false-occluder predicate. Keep the existing HOM output diagnostic-only; do not use its filled coverage to suppress work.

Direct Metal loads authoritative level geometry through `LoadR4LevelGeometryWithBytes(levelDirectory, scene.geometry, scene.geometryBytes, ...)` (`src/Layers/xrRenderMetal/MetalBootstrap.mm:1135-1136`). The parsed `R4StaticVisual` records provide vertex/index spans, shader identity, transforms, and referenced bounds; `LevelScene::TextureMaterial` maps explicitly admitted visuals and carries the shader name, transform, and draw ranges. `drawLevelScene` iterates the active static visuals, applies validity, material/pipeline, and optional LMH-frustum admission, then submits their actual indexed draws (`src/Layers/xrRenderMetal/MetalBootstrap.mm:3389-3521`). The G-buffer is cleared immediately before that path (`src/Layers/xrRenderMetal/MetalR4EngineScene.mm:4145-4156`). This identifies a narrow source set for a future observer: only static visuals admitted by the same G-buffer path.

The raw CPU geometry bytes are temporary. `uploadLevelScene` reads them for vertex and index uploads (`src/Layers/xrRenderMetal/MetalBootstrap.mm:2914-2933`), and `commitLevelSceneUploads` clears and shrinks `scene.geometryBytes` after the first successful submit (`src/Layers/xrRenderMetal/MetalBootstrap.mm:3028-3048`, called by `MetalR4EngineScene::OnFrameSubmitted` at `src/Layers/xrRenderMetal/MetalR4EngineScene.mm:7356-7360`). A diagnostic needing current installed mesh data across frames would have to extract a bounded subset before that clear, or reload the same configured level source. Parsed metadata alone cannot recover vertex positions after the byte buffer is cleared.

A conservative diagnostic candidate would use only original indexed triangles from the exact admitted static set. Exclude `def_aref` and unknown or translucent materials, plus dynamic/skinned renderables, flora/detail grass, HUD, water, and other passes. Missing those occluders can only reduce reported coverage. Never fill holes or replace triangles with visual bounds. A separate bounded CPU raster could mark a cell occluded only when its entire footprint is analytically covered by opaque triangles, using the farthest depth and a strict margin; partial cells, clipping ambiguity, and invalid geometry remain visible. A 64×64 32-bit depth grid is 16 KiB, but extraction and per-frame raster CPU cost have not been measured. Any diagnostic byte/triangle cap must fail open, and the existing `CHOM::propagade()` fill must not be reused for this predicate.

The frozen whole-light observer provides a narrower initial screen: complete submitted groups with `zero_deferred_receiver_samples`, correlated with the existing per-tile `static_rows`, `static_encoded_draws`, `dynamic_submitted_draws`, and `static_transform_bytes`. These are workload counts, not milliseconds saved. `METAL_LMH_FRUSTUM` reports camera-frustum admission only; it does not establish HOM-hidden work. Do not convert row, draw, or byte counts into time or FPS estimates.

A suggested screening signal for considering a bounded installed-geometry raster prototype is the same complete parent producing zero deferred receiver samples in two separate successful acquired-frame receipts while its associated tiles contain actual static shadow draws or rows. This is only a prioritization screen: it grants no culling or suppression permission. Any suppression would still require separate conservative-coverage validation, rendering correctness proof, and fixed-condition same-binary A/B. Stop the branch if receipts are incomplete/nonzero or the candidate groups have no corresponding shadow work.
