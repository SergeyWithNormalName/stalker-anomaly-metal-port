## Главные подтверждённые исправления и отложенные причины

**Lua numeric boundary.** Два `CEntity::ChangeTeam` crash IPS из V1 BVH arms показывают один и тот же squad=6664, прочитанный через unchecked 256-entry `CTeamHierarchyHolder::squad`. ARM64 typed callback получал Lua double через `fcvtzs w23,d0` и передавал полный register дальше; bound check отсутствует в release. Проблема в numeric narrowing UB, не доказательство renderer corruption или null object. Пять narrow converter policy изменены, сохранена Windows-подобная low-byte/word wrapping для finite values; Windows generic word/NaN контракт не утверждается. Raw материалы: [change-team-crash-triage.md](<XRAY_SOURCE_ROOT>/scratch/gameplay-rescue-20260929/change-team-crash-triage.md), ARM64/Windows disassembly рядом.

**ModelPool empty query.** Пустой `CModelPool::Exists` запрос вызывал путь создания/загрузки модели из сетевого `CHangingLamp` spawn. V4 ранний false guard для null/empty query и live guard-hit/normal exit подтверждены. Не расширять claim до доказательства причинности всех FileDownload ошибок. Текущий source in V4/V9 manifest `src/Layers/xrRender/ModelPool.cpp`, SHA `71490713de348d5f98f4aec92aac9c41c3f9edbfdf3e3791c23c3d1efae43ba1`.

**Shadow depth/flora.** Depth correction была обязательной, потому что старый tree PS писал константу/цвет, а не raster depth. Новые cooker wrappers для opaque/AREF vertex main сохраняют clip и возвращают `rasterPosition.z` в R32; `compile_r4_shadow_casters_msc.sh` и prestate лежат в `active-occlusion-stage`/`prestate/flora-depth-output`. Actual GPU oracle old negative/new positive, alpha clip preserved. Flora instancing имеет CPU/штучные synthetic/реальные local+sun shader oracle receipts, включая wind states; candidate build bundle — `flora-shadow-instanced-e08`. Использовать только с точными receipt/metallib hashes, не подменять GAMMA mod files.

**Dynamic shadow BVH/readiness.** Preparation state/work indices сделаны per-current-prewarm epoch с fallback на старый путь при unknown/rebuild/error; V4 GPU/runtime проверил 282,000 views, 0 fallback/miss в указанном screen. Не менялся main camera culling. Доказательства и prestate лежат в `prestate/dynamic-prepared-state`, `dynamic-epoch-draft`, `qualification/dynamic-epoch` и V4/V5 logs.

**Rejected/inconclusive claims.** DefVertex V2 A/B нейтральный; V4 combined A/B условный (экран был locked, нет visual/motion acceptance); V7 ABBA показывает направление combined work, но только Lua callback throughput с заметной baseline variability; V8 static grouping регрессировала на единственной off/on паре без доказанного механизма и удерживается default-off. HOM и V6/V7 whole-light counts — proxy/observer only. Ни одна из этих строк не равна accepted render speedup.

## Возможные направления для будущего scope

Это предложения для следующего Sol, а не разрешение выполнять дополнительную работу сейчас. Текущая rescue-сессия завершена по принятому V9r1 решению; никаких дополнительных game/build/GPU действий в этом handoff нет.

1. **Если V9r1 catalog и CPU/GPU join полезны, следующий доказательный шаг — shadow/deferred raster correctness, не suppression.** Проверить actual qualified MSC opaque/AREF shader pair, source/material receipt identity, viewport/cull/depth/stencil state, exact admitted triangles, WVP/jitter и per-pixel coverage. На normal depth production GPU-depth oracle должен подтвердить для каждого CPU-covered cell `actual GPU depth <= CPU conservative farthest depth`; background/deeper/out-of-range/unknown — fail-open. Проверить все потребители visibility, камеру/motion/near plane и layered/translucent/volumetric/HUD constraints. Current zero deferred receiver count не достаточен; suppression не является частью принятой работы.
2. **Для performance — использовать уже измеренный CPU бюджет, не прежний HOM estimate.** Основной source-level opportunity в full report — local-shadow CPU: Windows/Silo comparison видит13.67/31.56ms в двух разных native scenes; V5 attribution отдельным V5 кандидатом дала13.40ms p50 local-shadow CPU при locked-display/instrumented condition. Это разные runs/версии, не дельта. Любая будущая оптимизация должна иметь invariant work oracle, fallback для неизвестной мод-геометрии и same-binary, same-save/weather/camera repeated off/on windows; фиксировать callback vs presented метрику, frame gaps, visual/motion artifacts, workload counters и resource/environment state отдельно. V9r1 CPU observer стоит в среднем около4.2ms/grid build +0.2ms/query, поэтому любой расширенный selector/grid обязан показать, что дополнительная coverage и полезная корреляция оправдывают этот расход. Следующий выбор может быть production per-cell depth validation, сокращение CPU подготовительной стоимости или отказ от grid-направления, если полезные доказательства не окупают его цену. Отдельный неимплементированный кандидат — immutable compute-bounds certificate: он был отложен, потому что измеренная оставшаяся gate была мала; возвращаться к нему только при новом source-level доказательстве ROI. Ни один certificate не должен незаметно обходить текущие exact source/world bounds, finite checks и fallback для unknown poses. Ещё один design-only кандидат — upload immutable constant slices один раз на acquired epoch вместо текущих повторных Shared-buffer MSC копий; до этого требуется явная epoch admission/validation на каждом bind, ownership через discard/retry и byte-identical shader inputs. Не хранить frame slice через epoch.
3. **Сравнить существующий combined compute-skin/dynamic-BVH/flora пакет на живом движении/изображении только при новом разрешённом scope.** V7 ABBA callback direction положительный, но baseline менялся 14.58→11.11/s, combined близок18.88→18.92/s; это не displayed FPS и не visual acceptance. До performance claim нужны движущиеся actor/vegetation/shadow cases и renderer-native/visible capture, actual route counters, stable scene inputs, repeats. Compute-skin oracle exact-byte and discard/retry ownership already passed separately; no reason to rerun numeric oracle absent regression. При возможной GPU prequery оптимизации сохранить правила текущего приобретённого frame: submit не является flush/sync и не разрешает второе сцено-prewarm; нужен доказанный mid-frame resume и command/resource ownership, прежде чем заменять CPU query.
4. **Static constant grouping остаётся negative hold.** Единственная V8 same-binary off/on pair была one-direction screen: −11.70% callback throughput, обратную пару не выполняли, причина результата неизвестна; никакого reverse pair/default promotion автоматически не запускать.
